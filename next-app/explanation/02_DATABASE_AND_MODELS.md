# 02. Database & Data Models

## 1. Database Connection
- **Provider**: MongoDB (MongoDB Atlas)
- **Driver**: Prisma Client (`@prisma/client`) via `src/lib/prisma.ts`
- **Configuration**: Set via `MONGODB_URI` environment variable in `.env`.

---

### 1. `Organization`
The primary multi-tenant root container.
- `id`: MongoDB ObjectId (`@map("_id") @db.ObjectId`).
- `name`: Organization name (e.g. "Medinova Health Network").
- `timezone`: Default clinic timezone (e.g. "Europe/London").
- `industry`: Default "Healthcare".
- **Relations**: Holds lists of `teamMembers`, `authUsers`, `patients`, `callRecords`, `appointments`, `notifications`, `usageEvents`, and `botSettings`.

### 2. `TeamMember`
Clinical and administrative practice staff (doctors, nurses, care coordinators).
- Fields: `name`, `role`, `shift` (e.g., "08:00-16:00"), `status` ("online", "busy", "on-call"), `isActive`.
- **Relations**: Links to `Appointment` as provider and `BotSettings` as urgent escalation contact.

### 3. `AuthUser`
Accounts for system login and authentication.
- Fields: `email` (unique), `displayName`, `role` ("admin" | "user"), `passwordHash`, `passwordSalt`, `defaultRoute`, `isActive`.
- **Security**: Passwords hashed using Node.js PBKDF2 (120,000 iterations, SHA-512, 16-byte random salt).

### 4. `Patient`
Practice patients receiving care or making appointments.
- Fields: `name`, `preferredLanguage` (e.g. English, Polish, Urdu), `riskLevel` ("standard", "high", "urgent").
- **Relations**: Linked to `CallRecord`, `Appointment`, and `Notification`.

### 5. `CallRecord`
Inbound/outbound voice call transcript and AI categorization record.
- Caller Information: `callerName`, `callerPhone`, `callerLanguage`.
- Clinical AI Triage:
  - `intent`: Extracted topic (e.g. "Cardiology follow-up", "Prescription refill").
  - `urgency`: "URGENT", "HIGH", "MEDIUM", "LOW".
  - `isSpam`: "SPAM", "NOT_SPAM", "NOT_SURE".
  - `callbackRequired`: "YES", "NO", "NOT_SURE".
  - `callbackRequiredReason`: Clinical justification.
  - `recommendedDepartment`: Suggested clinic ward.
  - `recommendedNextSteps`: JSON array of tasks generated by LLM.
- Telemetry: `startedAt`, `endedAt`, `durationSeconds`, `latencyMs`, `costUsd`.
- Raw Artifacts: `transcript` (Full conversational dialog).

### 6. `Appointment`
Scheduled visits booked by patients or clinical coordinators.
- Fields: `department`, `status` ("scheduled", "confirmed", "completed", "cancelled"), `channel` ("voice", "sms", "web"), `scheduledAt`, `durationMinutes`, `confirmationSent`, `calendarSynced`.
- **Relations**: Linked to `Patient` and optional `TeamMember` provider.

### 7. `Notification`
SMS and Email alerts triggered by urgent triage or appointment confirmations.
- Fields: `kind` ("sms_confirmation", "urgent_triage", "email_confirmation"), `channel` ("sms", "email"), `title`, `body`, `status` ("read", "unread"), `scheduledAt`, `readAt`.

### 8. `UsageEvent`
Granular cost and billing records.
- Fields: `source` ("LiveKit WebRTC", "LLM Inference", "Deepgram STT", "Cartesia TTS"), `minutes`, `costUsd`.

### 9. `BotSettings` & `BotLiveNumber`
Customizable assistant profile per organization and owner.
- Fields:
  - `botName`: e.g. "Medinova Assistant".
  - `language`: e.g. "English".
  - `accent`: e.g. "British".
  - `voiceModelName`: Current voice persona identifier.
  - `instructions`: System prompt instructions guiding conversational clinical tone and limits.
  - `crmSyncEnabled`, `calendarSyncEnabled`: EHR sync toggles.
  - `notifyTargetType`: "team_member" or "external".
  - `urgentTeamMemberId`: Staff member to alert on urgent call.
  - `emailTemplate`, `smsTemplate`: Text templates for urgent dispatch.
- `BotLiveNumber`: Phone numbers connected to specific departments/workflows.

### 10. `VoiceModel`
Catalog of pre-configured synthetic voice personas.
- Fields: `name`, `tone`, `accent`, `language`, `gender`, `sampleAudio`, `sortOrder`.

## 3. Database Provisioning & Management
Database collections are defined declaratively in `prisma/schema.prisma`. Schema synchronization with MongoDB Atlas is managed via Prisma CLI:
```bash
# Push schema definitions to MongoDB
npm run db:push

# Open graphical database inspector
npm run db:studio
```
